# SiteEcho 產品策略

## 1. 產品定位

SiteEcho 是一個 **LINE-first 的工地 Open Loop 助理**。

第一層對外價值：

> **工地上的事情，用說的就好。**

第二層留存價值：

> **交代過，不代表處理完。**

第三層商業價值：

> **哪些事情還沒下文，SiteEcho 幫你盯著。**

## 2. 真正要解決的問題

工程現場的困難不是「沒有地方記筆記」，而是：

-   同時有多個專案。
-   每個專案有多個工種。
-   每個工種同時存在大量待確認、待修改、待回覆事項。
-   資訊大量發生在現場口頭溝通、LINE、電話、照片與臨時筆記。
-   人通常記得「有這件事」，卻不一定記得後來的決議與處理結果。
-   「講過」與「處理完成」之間存在很長的 Open Loop。

因此 SiteEcho 的基本工作單位不是 Note，也不是 Day，而是 **Issue**。

## 3. 核心資料心智

``` text
Project
  ↓
Trade
  ↓
Issue
  ↓
Event
  ↓
Resolution
```

例：

``` text
內湖案
└─ 水電
   └─ 主臥插座位置
      ├─ 9/17 發現位置問題，暫停施工
      ├─ 9/19 設計師確認向左 10 cm
      ├─ 9/21 水電完成修改
      └─ Resolved
```

## 4. 與其他產品的區隔

### Report-first 產品

典型心智：

`今天發生什麼 → 整理 → Daily Report`

核心 Object = **Day**

### SiteEcho

典型心智：

`這件事情 → 後來發生什麼 → 現在完成了嗎`

核心 Object = **Issue**

SiteEcho 可以未來產生 Report，但 Report 是 Issue 資料的
Output，不是產品核心。

## 5. LINE-first 的戰略意義

LINE 本身就是第一眼差異化：

-   不用下載新 App。
-   台灣工程現場已有大量 LINE 使用習慣。
-   使用者不必先學習完整工程管理系統。
-   可以主動把未完成事項送回使用者面前。
-   LINE 的限制迫使產品保持簡單。

原則：

> **LINE 不是 App 的替代 UI，而是 SiteEcho 的現場工作介面。**

## 6. 中文／台灣在地化

差異化不只是繁體中文 UI。

SiteEcho 應理解台灣工程現場語言，例如：

-   收尾
-   封板
-   批土
-   放樣
-   木作
-   泥作
-   崁燈
-   收邊
-   洗孔
-   打底
-   洩水坡
-   矽利康
-   叫料
-   追加／減項
-   待確認
-   「先不要收」
-   「上次不是有講要改」
-   「叫水電處理一下」

長期可持續建立華語／台灣工程語料優勢。

## 7. 產品邊界

SiteEcho 不以成為 Procore 類大型平台為目標。

第一階段不做：

-   ERP
-   Gantt
-   完整排程
-   報價
-   請款
-   圖面管理
-   工程知識問答
-   完整公司權限系統
-   複雜任務管理

核心只有：

> **把現場說過但尚未完成的事情留在視野裡，直到它真正結束。**
