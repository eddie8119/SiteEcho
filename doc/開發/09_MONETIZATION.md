# SiteEcho 商業化假設

## 商業風險

Issue 有需求，不代表使用者願意為「整理 Issue」付費。

「幫你整理得比較漂亮」通常屬於 Nice-to-have。

因此 SiteEcho 不應主要販售：

> AI 幫你整理 Issue History。

## 商業價值重構

真正可收費的價值更接近：

> **降低遺漏、重工、追問與翻找紀錄的成本。**

對外語言：

-   交代過，不代表處理完。
-   工地最怕的不是事情多，是講過之後沒下文。
-   哪些事情還沒下文，SiteEcho 幫你盯著。

避免沒有證據的恐嚇式金額宣稱。

## 三層價值

### Acquisition

**工地上的事情，用說的就好。**

### Retention

**SiteEcho 記得同一件事情後來怎麼了。**

### Monetization

**SiteEcho 幫你找出還沒下文的事情並持續追到結束。**

## Report 的角色

不要因為競品都賣 Report，就永遠排除 Report。

但 SiteEcho 的 Report 應是 Open Issue / Trade data 的 Output。

例如：

> **內湖案｜水電待處理事項**
>
> 1.  主臥插座 --- 待修改\
> 2.  廚房迴路 --- 待確認\
> 3.  客浴插座 --- 待處理

這比 generic Daily Report 更符合 SiteEcho 核心。

-   分享給工班
-   PDF / LINE 待處理清單
-   Search
-   Export
-   Drive Sync
-   Team / Company
-   App / Web Power Features

## 初期不要過早定價

MVP 先驗證：

> 使用者是否因為 SiteEcho 少漏事情，而形成依賴。

之後才測： - 免費額度 - 個人 Pro - 小團隊方案

## Willingness-to-Pay 核心問題

不要只問：

> 「你願意付多少？」

而問：

> 「如果這個功能下個月要收費，你會留下還是回到 LINE / Notes？為什麼？」

真正競品是使用者既有的免費 workaround。
